# Ninja Kid Frontend

Phaser + TypeScript + Vite를 사용하는 실시간 보드게임 프론트엔드의 시작 구성입니다.
특정 보드 모양, 이동 규칙, 턴 순서, 승리 조건은 가정하지 않습니다.
현재 화면은 **오브젝트 선택·이동으로 구조를 확인하는 로컬 시연**입니다.
트레일러의 실제 게임 규칙이나 멀티플레이 서버를 구현한 것은 아닙니다.

## 실행

Node.js 22.12 이상(22 계열) 또는 24 이상을 권장합니다.

```sh
npm install
npm run dev
```

표시된 로컬 주소를 브라우저에서 엽니다. 시작 버튼을 누른 다음 노란 오브젝트 A를 선택하고
보드의 빈 곳을 누르면 이동합니다. 상대 오브젝트 B는 시연용으로 고정되어 있습니다.
작은 화면에서는 전체 게임 화면을 같은 비율로 축소합니다. 모바일 전용 UI는 아직 없습니다.

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

`build`는 타입 검사 후 배포할 정적 파일을 `dist/`에 생성합니다.

## 디렉토리와 책임

```text
src/
├─ main.ts                      # 앱 시작과 개발 중 종료 처리
├─ app/                         # Phaser 실행, 화면 크기와 배율, 전체 CSS
├─ scenes/                      # 로딩·대기실·대국 화면 조립과 수명 관리
├─ features/
│  └─ match/
│     ├─ match-types.ts          # 경기 상태, 플레이어, 오브젝트, 행동
│     ├─ match-session.ts        # 요청 전송과 서버 상태 반영
│     ├─ demo-transport.ts       # 서버 없이 실행하는 로컬 시연
│     ├─ BoardView.ts            # 보드와 오브젝트 표시, 입력 좌표 변환
│     └─ MatchHud.ts             # 연결 상태, 안내 문구 표시
└─ network/                     # WebSocket 연결, 메시지 검증, 통신 인터페이스
docs/network-protocol.md         # 임시 서버 통신 계약
public/assets/                  # 추후 사용할 이미지와 사운드
```

- `Scene`은 화면을 조립합니다. 서버 메시지 처리나 게임 규칙을 몰아넣지 않습니다.
- 경기 타입과 세션은 Phaser를 가져오지 않습니다. 화면과 별도로 검증할 수 있습니다.
- 게임 데이터는 `MatchSession`이 보관하는 하나의 스냅샷을 기준으로 표시합니다.
  `BoardView`가 별도로 관리하는 선택 표시는 화면 상태이며 경기 상태가 아닙니다.
- `network`는 전송과 외부 데이터 검증을 담당합니다. 승패나 이동 가능 여부를 판단하지 않습니다.
- 게임마다 다른 기능은 `features/` 아래에 추가합니다. 대기실에 실제 기능이 생기면
  `features/lobby/`를 만들고, 여러 기능에서 재사용하는 UI가 생기면 `shared/ui/`를 만듭니다.
  아직 사용하지 않는 빈 추상 계층은 만들지 않습니다.
- 대국 Scene 종료·파괴 시 구독과 연결을 정리해 화면 재진입 시 중복 처리를 방지합니다.

## 실제 게임을 연결할 위치

1. `match-types.ts`에서 실제 상태와 행동을 정의합니다. 현재 `move`는 시연용 예시입니다.
   보드 좌표는 0~1의 표시 비율이며 칸·교차점·게임 규칙 좌표가 아닙니다.
   실제 보드의 구조가 정해지면 도메인 좌표와 화면 좌표 변환을 별도로 정의합니다.
2. `BoardView.ts`에서 보드 모양, 캐릭터·말의 표현, 선택 및 애니메이션을 구현합니다.
   리소스는 `public/assets/`에 두고 `PreloadScene`에서 로딩합니다.
3. 서버 API가 정해지면 `network/protocol.ts`의 타입과 검증기를 함께 수정합니다.
4. `match-session.ts`에서 서버 응답을 반영합니다. 요청만으로 확정 상태를 바꾸지 않습니다.
   현재는 전체 스냅샷을 받고 이전 버전과 중복 버전을 무시하는 방식입니다.
5. 로그인·방 검색·매칭 기능은 서버 계약이 정해진 뒤 추가합니다.

실제 서버를 쓰려면 `.env.example`을 `.env.local`로 복사하고
`VITE_GAME_SERVER_URL`에 `ws://` 또는 `wss://` 주소를 지정한 뒤 개발 서버를 재시작합니다.
주소가 없으면 `DemoTransport`를 사용합니다. `VITE_` 설정은 브라우저에 공개되므로 비밀키를 넣지 않습니다.

현재 서버 모드는 연결과 메시지 송수신을 위한 어댑터만 제공합니다. 서버 자체, 인증,
자동 재연결, 방 복귀, 지연 보정은 포함하지 않습니다. 연결이 끊기면 입력을 차단하고,
대기실로 돌아가 다시 시작하면 새 연결로 전체 상태를 요청합니다.

테스트는 서버 확정 전 상태 유지, 오래된 상태 무시, 구독 해제, 로컬 행동 처리,
잘못된 서버 메시지 차단을 확인합니다. 실제 게임 규칙 테스트는 규칙 구현 시 추가합니다.
