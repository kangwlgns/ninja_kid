# 임시 경기 통신 계약

실제 서버 API가 없는 상태에서 프론트엔드 경계를 정하기 위한 예시입니다.
서버 구현이 이 계약을 지원할 때만 서버 모드를 사용할 수 있습니다.
WebSocket의 JSON 텍스트 메시지를 사용합니다.

## 경기 참가

클라이언트는 연결이 열린 뒤 아래 요청을 보냅니다.

```json
{ "type": "join", "matchId": "preview-room" }
```

서버는 인증된 세션에 맞는 `playerId`와 해당 플레이어에게 공개할 수 있는 전체 상태를 반환합니다.
아래 예시는 인증을 구현하지 않습니다. 운영 서버는 연결 시 인증과 경기 참가 권한을 검사해야 합니다.
숨겨진 정보가 있는 게임이라면 플레이어별 스냅샷을 생성해야 합니다.

```json
{
  "type": "snapshot",
  "playerId": "player-1",
  "state": {
    "matchId": "preview-room",
    "revision": 0,
    "phase": "playing",
    "players": [
      { "id": "player-1", "name": "Player 1" },
      { "id": "player-2", "name": "Player 2" }
    ],
    "entities": [
      {
        "id": "entity-1",
        "ownerId": "player-1",
        "label": "A",
        "position": { "x": 0.25, "y": 0.5 }
      }
    ]
  }
}
```

`revision`은 경기 내 단조 증가하는 안전한 정수입니다. 같은 연결에서 이미 적용한 버전 이하의
스냅샷은 무시합니다. 새 연결에서는 전체 스냅샷을 다시 받습니다.
`phase`는 `waiting`, `playing`, `finished` 중 하나입니다. 종료 상태에서는 행동 입력을 막습니다.
표시 좌표는 0~1의 비율입니다. 보드 크기나 격자 개수, 턴 기반 진행을 가정하지 않습니다.
예시 오브젝트는 소유 플레이어가 있지만, 실제 게임에서 중립 오브젝트 등이 필요하면 타입과 검증을 확장합니다.

## 행동 요청

```json
{
  "type": "action",
  "matchId": "preview-room",
  "expectedRevision": 0,
  "action": {
    "kind": "move",
    "entityId": "entity-1",
    "position": { "x": 0.4, "y": 0.6 }
  }
}
```

서버는 요청자의 권한, 경기 상태와 행동을 검증한 후 새 버전의 `snapshot`을 전달합니다.
현재 시연에서는 버전이 다른 요청을 거절합니다. 실제 게임의 동시 행동 처리 정책은 서버와 함께 정합니다.
클라이언트의 플레이어 ID를 신뢰해 행동 권한을 결정해서는 안 됩니다.
게임의 실제 행동 종류와 응답 계약이 정해지면 이 예시를 교체합니다.

## 거절 또는 오류

```json
{ "type": "error", "message": "행동을 처리할 수 없습니다." }
```

연결이 끊기면 입력을 차단합니다. 자동 재연결과 요청 재전송은 아직 없으며,
나중에 추가할 경우 요청 ID, 중복 처리 방지, 전체 상태 복구 정책을 먼저 정의해야 합니다.
